## 项目概述

RuoYi-WMS 是一套基于 RuoYi（v3.7.0）企业级开发底座构建的**开源仓储管理系统**（Warehouse Management System），面向中小型制造、贸易与第三方物流企业，覆盖从物料建档、出入库作业到库存核算的完整仓配业务闭环。

系统采用前后端分离架构，前端基于 Vue + Element UI，后端基于 Spring Boot + Spring Security，集成 MyBatis-Plus、Redis、JWT 与 Quartz 定时任务框架。业务上实现了入库、出库、移库、盘点、月结等核心 WMS 能力，并支持 Lodop 与网页两种单据打印方式。

### 设计目标

- **开箱即用**：内置演示数据与初始化 SQL，提供完整的权限、字典、定时任务等基础能力，克隆即可运行。
- **业务完整**：覆盖入库 → 在库（移库 / 盘点）→ 出库的全链路作业，状态机驱动单据流转。
- **易于二次开发**：基于 RuoYi 代码生成器，新业务表可一键生成前后端 CRUD 代码，保持与框架一致的编码风格。
- **权限可控**：用户 / 角色 / 菜单 / 数据范围四级权限模型，支持按钮级权限与部门级数据隔离。

### 认证与权限模型

系统采用 **JWT 无状态认证**，登录成功后签发 Token，后续请求通过 `Authorization` 头携带，服务端解析校验。权限模型分四层：

1. **用户（sys_user）**：系统操作者主体。
2. **角色（sys_role）**：权限集合，绑定菜单与按钮权限。
3. **菜单（sys_menu）**：含目录、菜单、按钮三种类型，定义操作权限点（`system:user:list` 等）。
4. **数据范围（sys_role_dept）**：通过角色关联部门，实现按部门的数据隔离（本人 / 本部门 / 本部门及以下 / 全部 / 自定义）。

前端通过 `v-hasPermi` / `v-hasRole` 指令控制按钮可见性，后端通过 `@PreAuthorize` 注解做二次校验，形成前后端双重防护。

## 业务功能

### 功能全景

系统分为「系统管理」与「仓储业务」两大板块。

**系统管理**（RuoYi 底座自带）：

- 用户管理、部门管理、岗位管理
- 菜单管理、角色管理
- 字典管理、参数配置
- 操作日志、登录日志
- 在线用户、定时任务、服务监控、缓存监控
- 代码生成、系统接口（Swagger）

**仓储业务**（wms 模块，24 个控制器）：

| 模块 | 说明 |
|------|------|
| 基础数据 | 仓库 / 库区 / 货架、物料 / 物料分类、客户 / 供应商 / 承运商 |
| 入库管理 | 入库单及明细，采购入库 / 外协入库 / 退货入库 / 盘盈入库 |
| 出库管理 | 出库单及明细，销售出库 / 外协出库 / 调拨出库 / 领料出库 / 盘亏出库 |
| 移库管理 | 库内移库，调拨出入库 |
| 库存看板 | 实时库存查询，按仓库 / 库区 / 货架维度 |
| 库存记录 | 库存变动历史流水 |
| 盘点管理 | 盘点单及明细，生成盘盈入库 / 盘亏出库 |
| 月结管理 | 库存结算，按周期冻结期初 / 期末 |
| 波次管理 | 出库拣货波次，合并多张出库单统一拣货 |
| 单据打印 | 入库单 / 出库单，支持 Lodop 与网页两种打印 |

### 仓储拓扑数据模型

库存按「仓库 → 库区 → 货架」三级定位，每条库存记录绑定到具体货架：

```
Warehouse (仓库)
  └── Area (库区)
        └── Rack (货架)
              └── Inventory (库存：物料 + 数量)
```

核心业务表关系（简）：

```
Item (物料)
  │
  ├──< Inventory (库存)  ── Warehouse/Area/Rack
  │
  ├──< ReceiptOrder >── ReceiptOrderDetail (入库单/明细)
  │
  ├──< ShipmentOrder >── ShipmentOrderDetail (出库单/明细)
  │
  ├──< InventoryMovement >── InventoryMovementDetail (移库单/明细)
  │
  ├──< InventoryCheck >── InventoryCheckDetail (盘点单/明细)
  │
  └──< InventorySettlement >── InventorySettlementDetail (月结单/明细)
```

所有业务单据均配有「主表 + 明细表」结构，明细记录具体物料的数量与库位，主表记录单据头信息、状态与金额。

### 单据状态机

系统用整数状态码驱动单据流转，保证作业过程可追溯、可回退、可作废。

**入库单状态流转**（`receiptOrderStatus`）：

| 状态码 | 含义 | 说明 |
|--------|------|------|
| 0 | 未入库 | 单据新建 |
| 1 | 在途 | 已发货、未到货入库 |
| 2 | 部分入库 | 明细部分已入库 |
| 3 | 全部入库 | 明细全部入库完成 |
| 4 | 作废 | 单据作废 |

入库类型：采购入库（1）、外协入库（2）、退货入库（3）、盘盈入库（32）。

**出库单状态流转**（`shipmentOrderStatus`）：

| 状态码 | 含义 | 说明 |
|--------|------|------|
| 11 | 未出库 | 单据新建 |
| 12 | 部分出库 | 明细部分已出库 |
| 13 | 全部出库 | 明细全部出库完成 |
| 14 | 作废 | 单据作废 |

出库类型：销售出库（11）、外协出库（12）、调拨出库（13）、领料出库（14）、盘亏出库（31）。

**移库单状态流转**（`movementStatus`）：

| 状态码 | 含义 |
|--------|------|
| 21 | 未操作 |
| 22 | 部分移动 |
| 23 | 移动完毕 |
| 24 | 作废 |

> 说明：入库 / 出库 / 移库共享同一套状态码命名约定（`NOT_IN → PART_IN → ALL_IN`），便于在通用查询与前端展示层统一处理。

### 库存核算逻辑

每一次出入库、移库、盘点的操作都会触发库存变动，并同步写入 `wms_inventory_history` 流水表，形成完整的库存审计链路：

1. 入库：`Inventory.quantity += 入库数量`，写入正向流水。
2. 出库：`Inventory.quantity -= 出库数量`，写入负向流水。
3. 移库：源库位扣减、目标库位增加，记录移库流水。
4. 盘点：按实盘数量与账面数量差额，生成盘盈入库 / 盘亏出库单据。
5. 月结：按周期对库存快照结算，记录期初 / 期末数量与金额。

## 部署与运行

### 环境要求

- JDK 1.8
- MySQL 5.7+（建议 8.0）
- Redis 5.0+
- Maven 3.6+
- Node.js 14+

### 后端启动

```bash
# 1. 导入初始化数据
mysql -u root -p wms < wms-ruoyi/sql/结构和数据.sql

# 2. 修改数据库与 Redis 连接
# wms-ruoyi/ruoyi-admin/src/main/resources/application-druid.yml
# wms-ruoyi/ruoyi-admin/src/main/resources/application.yml

# 3. 编译打包
cd wms-ruoyi
mvn clean package -DskipTests

# 4. 运行
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

### 前端启动

```bash
cd ruo-yi-wms-vue
npm install --registry=https://registry.npmmirror.com
npm run dev          # 开发模式
npm run build:prod   # 生产构建
```

## 安全与最佳实践

- **凭证隔离**：`application-dev.yml` / `application-prod.yml` 已在 `.gitignore` 中忽略，生产环境数据库密码不入库。
- **接口鉴权**：所有业务接口默认需要登录态，关键操作叠加 `@PreAuthorize` 权限注解。
- **操作审计**：通过 AOP 自动记录操作日志（`sys_oper_log`），可追溯谁在何时做了什么。
- **SQL 注入防护**：MyBatis 参数化查询，杜绝字符串拼接。
- **数据软删除**：业务表统一使用 `del_flag` 逻辑删除标识，误删可恢复。
